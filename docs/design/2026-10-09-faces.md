# Face detection and grouping design

Date: 2026-10-09
Status: draft, pending review

## Goal

Find faces in every frame during ingest, embed them, and group the faces of the same person across all media. The People screen in the desktop app (`listPeople`, `renamePerson`) and the face overlays (`getDetections`) read the result.

The mechanism is ported from voogle-v2 (Swift: Apple Vision + a GhostFaceNet Core ML model + centroid/Louvain grouping). Probes found bugs and loose thresholds in voogle's version, so this design changes those parts. Every change is backed by a measurement in [Findings](#findings).

## Phases

The work is built in two phases. Phase 2 starts only after phase 1 meets its done criteria and is merged to `main`.

| Phase | Delivers | Done when |
|---|---|---|
| **1. Detection and embedding** | The `faces` ingest module: detect, gate, align, embed, and store one result per face | The [phase 1 tests](#phase-1-tests) pass, including the LFW pair accuracy check, and a manual ingest of a real folder stores faces at the expected speed |
| **2. Grouping** | `snapsort/group.py`: person tables, the grouping algorithm, `snapsort group`, and grouping at the end of `snapsort ingest` | The [phase 2 tests](#phase-2-tests) pass, including exactly 3 persons on voogle's photo set and the two-pass LFW grouping check |

Phase 1 alone already gives the frontend face boxes (`getDetections` with `personId: null`) and `faceCount`. Phase 2 adds persons.

## Scope

In:

- Phase 1: the `faces` module, its test file, its dependencies and the model file.
- Phase 2: `snapsort/group.py`, its tests, `networkx`, and the `cli.py` change.

Out:

- the API layer that serves `listPeople`, `renamePerson` and `getDetections`. This doc only fixes the data they read.
- face crop images for `faceRef`
- merge, split, hide and reassign. The v1 frontend dropped them.
- a full regroup that rebuilds every person from scratch
- non-macOS support

## Findings

These are the probes that shaped the design. The data was voogle's labeled set (19 photos of 3 people, 23 faces), 150 frames at 1 fps from two talking-head videos of one person, and LFW (13,233 photos of 5,749 people).

| Phase | Topic | Finding | Effect on this design |
|---|---|---|---|
| 1 | voogle's detector setup | The landmarks request alone returns confidence 1.0 for every face, no pitch, yaw only in {0, ±45} and roll only in {0, ±30}. voogle's confidence and pitch checks never fire, and its yaw and roll checks are coarse. | Run the rectangles request (revision 3) first and pass its faces into landmarks and quality. This gives real confidence (0.61–0.87) and continuous angles at the same cost (25.5 vs 25.6 ms per frame). |
| 1 | voogle's quality matching | Vision returns capture-quality results in a different order from the faces. Pairing them by index gave the wrong face's quality in 3 of 4 two-person photos. | Match quality to faces by bbox. |
| 1 | Fast filter | A downscaled face-rectangles pre-check costs 13–20 ms, compared with 26 ms for full detection. It saves at most about 10 ms, and only on frames with no face. | No separate pre-check. The rectangles request is the first step, and "no faces" ends the frame. |
| 1 | Quality check | Selfie video frames score 0.16–0.5 and photos 0.44–0.78. voogle's floor of 0.5 dropped 125 of 126 video faces. Closed eyes lower the score too, yet those faces still embedded correctly (0.84–0.91 to their own person). | No quality floor. Quality is stored in `data` so a floor can be added later. |
| 1 | Yaw | A 25° limit dropped clearly visible photo faces at 30–34°. With 45°, every photo face grouped correctly. Head-turned video frames (29–41°) overlap with good faces, so no yaw value separates them. | Yaw ≤ 45°. |
| 1 | Roll | Alignment removes roll. The only face the roll check rejected (36.5°) grouped correctly without it. | No roll check. |
| 1 | Pitch | On LFW, 95 faces failed pitch > 25°. With the revised check, LFW pair accuracy rose from 99.43% to 99.67%. | Keep pitch ≤ 25°. |
| 1 | Model | The Core ML package matches the original Keras weights (cosine 1.0000 on 23 crops). Python alignment matches voogle's Swift crops (median cosine 0.981, worst 0.949). | Reuse voogle's `GhostFaceNetV1.mlpackage` unchanged. |
| 1 | Speed | Per 1080×1920 frame: detect 21 ms, align 14 ms (whole-frame resize), embed 1.2 ms per face. | Crop around the face before resizing. Target about 25 ms per frame, roughly 20 min per 50k frames. |
| 2 | Grouping threshold | Full Louvain grouping of 13,039 LFW faces. At 0.45 (voogle), 5 pairs of real people merged, including sisters Serena and Venus Williams. 0.50 merged the sisters. 0.55 merged nobody. Share of photos in their person's main group: 99.4%, 99.1% and 98.0%. | 0.55 for all grouping. Splits cost a little recall. Merges cannot be undone in v1. |

## Phase 1: detection and embedding

### Module (`snapsort/modules/faces.py`)

```python
class Faces(Module):
    name = "faces"
    version = "1"

    def setup(self) -> None: ...
    def process(self, frames: list[Frame]) -> list[Result]: ...
```

`setup()` loads `snapsort/models/GhostFaceNetV1.mlpackage` with `coremltools.models.MLModel(path, compute_units=ComputeUnit.ALL)`.

`process(frames)` handles each frame as follows:

1. **Detect.** Convert the frame to a `CGImage` (RGBA bytes → `CGImageCreate`). Run `VNDetectFaceRectanglesRequest` (default revision 3 on current macOS). No faces means no results for this frame.
2. **Landmarks and quality.** Set the rectangle results as `inputFaceObservations` on `VNDetectFaceLandmarksRequest` and on `VNDetectFaceCaptureQualityRequest`, then run both on the same image. Landmark results keep the rectangle order, angles and confidence. Pair each quality result with the face whose bbox it matches (IoU > 0.9). A face with no match gets `quality = None`.
3. **Gate.** Keep a face only if every check below passes. A missing angle passes its check.

   | Check | Keep if |
   |---|---|
   | Confidence | ≥ 0.5 |
   | Face size | box ≥ 60 px on both sides, measured on the full-resolution frame |
   | Landmarks | left pupil, right pupil, nose and outer lips all present |
   | Yaw | \|yaw\| ≤ 45° |
   | Pitch | \|pitch\| ≤ 25° |

4. **Align.** Each pupil position is the mean of its landmark points, converted to top-left pixel coordinates. Find the similarity transform (scale, rotation, translation) that moves the pupils onto the ArcFace 112×112 eye positions (38.2946, 51.6963) and (73.5318, 51.5014). First crop a square around the face (1.5× the box) and shrink it so the transform scale is about 1. Then warp to 112×112 with PIL bicubic, filling outside pixels with black.
5. **Embed.** Make one `predict` call with every crop in the batch. The model does its own `(pixel − 127.5) / 128` normalization. L2-normalize each 512-d output.

One `Result` per kept face, matching the pipeline's "Face" row:

| Field | Value |
|---|---|
| `label` | `"face"` |
| `score` | Vision confidence |
| `bbox` | x, y, w, h, normalized 0–1 with a top-left origin, clipped to the frame. Vision boxes can extend past the edge: up to 20% of the box in the probe videos. `validate()` rejects values outside [0, 1]. |
| `vector` | 512 float32, unit length |
| `data` | `{"yaw": .., "pitch": .., "roll": .., "quality": ..}` in degrees and 0–1, with `null` when Vision gives none |

Notes:

- The module never mutates `Frame.image`. Conversions and crops are copies.
- Vision gets the full-resolution frame. Images above 4K are untested for speed and memory.
- Changing the model, the alignment or the gate requires a `version` bump, which re-runs the module on every media file. Once phase 2 exists, grouping matches the new face results back to the existing persons (see [Re-ingest](#re-ingest)).

### Model

`snapsort/models/GhostFaceNetV1.mlpackage` (8.2 MB) is copied unchanged from voogle-v2 (`Sources/VoogleVision/Resources/`).

- GhostFaceNetV1 (W1.3, S1), an ArcFace-loss face recognition model trained on MS1MV2.
- voogle converted it with coremltools to an fp16 ML program from a Keras `ghostfacenet_v1.h5`. The source of the `.h5` file is not recorded.
- The GhostFaceNets code repository is MIT. MS1MV2 is derived from Microsoft's withdrawn MS-Celeb-1M and is commonly treated as research-only. See [Open decisions](#open-decisions).

`snapsort/models/` is a plain data directory outside `snapsort/modules/`, so module discovery never sees it.

### What the frontend can read after phase 1

| Frontend | Source |
|---|---|
| `getDetections(mediaId, ts).faces` | `faces` results of the frame at that `ts`. `box` = `bbox`, normalized with a top-left origin. `personId` is `null` until phase 2. There is a row for every 1 fps frame where a face passed the gate. |
| `MediaSummary.faceCount` | number of `faces` results in the media file's frames |

This answers the frontend's open question 6 (detection format).

### Errors

No module-specific handling beyond the pipeline's:

- `pyobjc` or `coremltools` missing, or not running on macOS: the import fails and discovery skips `faces.py` with a warning.
- The model fails to load: `setup()` raises, and the module is dropped for the run and retried on the next run.
- A Vision request returns an error: `process()` raises, and that file gets an `error` runs row while other modules continue.

### Dependencies

```
uv add pyobjc-framework-Vision pyobjc-framework-Quartz coremltools
```

All of them ship cp312 macOS arm64 wheels. `coremltools` runs predictions only on macOS. Nothing leaves the machine.

1. `setup()`, then `process(sample_frames)` passes `validate`. The shared fixtures (a red image and an ffmpeg `testsrc` video) contain no faces, so the result list is empty.

Env-gated checks (skipped unless the variable is set). The repo commits no binary fixtures.

  - every photo yields at least one face
  - all 23 faces pass the gate
  - the 4 two-person photos give 2 faces each

- Children, blurry or dark frames, small faces in group photos, and images above 4K.
- Speed of the crop-first alignment (the 25 ms target).

## Phase 2: grouping

### Interface (`snapsort/group.py`)

```python
def run_grouping(data_dir: Path) -> GroupSummary:
    """Assign every face result without a person. Returns counts of faces assigned
    and persons created. Does nothing when there are no unassigned faces."""
```

### Tables

`group.py` creates these with `CREATE TABLE IF NOT EXISTS` on top of the pipeline's `connect()`, which already turns on foreign keys.

```sql
CREATE TABLE IF NOT EXISTS persons (
  id         INTEGER PRIMARY KEY,
  name       TEXT,                                                -- set by renamePerson
  face_id    INTEGER REFERENCES results(id) ON DELETE SET NULL,  -- representative face, for faceRef
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE IF NOT EXISTS person_faces (
  result_id INTEGER PRIMARY KEY REFERENCES results(id) ON DELETE CASCADE,
  person_id INTEGER NOT NULL REFERENCES persons(id) ON DELETE CASCADE,
  score     REAL NOT NULL          -- similarity that placed the face; 1.0 for a new person
);
CREATE INDEX IF NOT EXISTS person_faces_person ON person_faces(person_id);
CREATE TABLE IF NOT EXISTS person_centroids (
  person_id INTEGER NOT NULL REFERENCES persons(id) ON DELETE CASCADE,
  slot      INTEGER NOT NULL,
  vector    BLOB NOT NULL,         -- little-endian float32, unit length
  weight    INTEGER NOT NULL,      -- appearances in this centroid
  PRIMARY KEY (person_id, slot)
);
```

Centroids hang off persons, not faces. A person and their name survive the deletion of all their face results.

### Algorithm

The constants below are voogle's, except the threshold:

```python
THRESHOLD = 0.55       # cosine; within one media file and across files
CENTROIDS = 20         # per person
KMEANS_ITERS = 20
SEED = 42
```

All steps run in one transaction:

1. **Load.** Read every `faces` result with no `person_faces` row, together with its frame's `media_id` and its vector.
2. **Collapse per media file.** Within each media file, link faces whose cosine ≥ `THRESHOLD`, using single link (union-find over pairs, computed in row chunks so memory stays flat on long videos). Each connected set is one *appearance*, with its vector set to the L2-normalized mean of its faces. Two people in the same photo or video stay apart, because the highest different-person cosine measured was 0.28.
3. **Match to existing persons.** Score each appearance against every stored centroid and take the best one. If it is ≥ `THRESHOLD`, all faces of that appearance join that person, with `score` = the best cosine.
4. **New persons.** Build a graph over the leftover appearances with an edge wherever cosine ≥ `THRESHOLD`, weighted by the cosine. Run `networkx.community.louvain_communities(weight="weight", seed=SEED)`. Each community becomes a new person, and so does each isolated appearance.
5. **Refresh touched persons.**
   - Centroids: rebuild from the person's appearances, one L2-normalized mean per media file over all the person's faces in that file. With ≤ `CENTROIDS` appearances, each one is a centroid with weight 1. Otherwise run spherical k-means: k-means++ initialization with distance `1 − cos`, assignment by max dot product, normalized means, up to `KMEANS_ITERS` iterations, seeded with `SEED`. Empty slots are reseeded from the farthest members of the largest cluster.
   - `face_id`: the person's face with the largest box area × confidence (voogle's rule). Persons whose `face_id` became NULL are refreshed too.

Grouping is idempotent: a second run with no new faces does nothing.

### When it runs

- `snapsort group` runs it on demand. Exit code 0, or 2 when there is no database.
- `snapsort ingest` calls `run_grouping` after `run_ingest` when the `faces` module was among the modules run. The frontend expects people to refresh when ingest finishes. This is a small change to `cli.py` only. `ingest.py` is unchanged.
- One line of output: `grouping  <n> faces  <m> new persons  <k> joined existing`.

### Re-ingest

When the `faces` module re-runs on a file (version bump or an earlier error), the pipeline deletes that file's face results and inserts new ones. Their `person_faces` rows cascade away, and the representative `face_id` may become NULL. The next grouping run treats the new faces as unassigned and matches them to the stored centroids, so they rejoin the same person ids and names.

### What the frontend can read after phase 2

| Frontend | Source |
|---|---|
| `getDetections(mediaId, ts).faces[].personId` | `person_faces.person_id` of that face result |
| `MediaDetail.people` | distinct persons over the media file's face results |
| `Person { id, name, count, faceRef }` | `persons` row. `count` = number of media files with a face of the person. `faceRef` is built from `face_id` (frame path + bbox). |
| `renamePerson(id, name)` | `UPDATE persons SET name = ?` |

Which persons `listPeople` returns is an open decision (see below).

### Errors

- Grouping fails: the transaction rolls back, nothing is written, and the error is printed. `snapsort group` exits with code 1, and `snapsort ingest` exits with code 1.
- Grouping while another `snapsort` process writes can hit "database is locked". This is the same known limit as two concurrent `ingest` runs (TASKS deferred list).

### Phase 2 tests

Grouping tests (`tests/group/test_group.py`), using synthetic unit vectors written straight into a temp database with no model:

1. Two well-separated sets of vectors become 2 persons.
2. Two faces in one media file with cosine < 0.55 become 2 persons. Two faces at ≥ 0.55 collapse into 1 appearance.
3. New faces near an existing person join that person, and no new person is created.
4. Deleting a person's face results and regrouping new, similar vectors returns the same person id and keeps the name.
5. A second run with no new faces changes nothing.

Env-gated checks:

- `SNAPSORT_FACE_TEST_DIR`: grouping gives exactly 3 persons with no mixing.
- `SNAPSORT_LFW_DIR`: grouping all photos in two passes (half, then the rest) exercises the centroid-match step. Pass criteria:
  - pair precision ≥ 99.5%
  - at most 1 group holds ≥ 2 photos of a second person (Sepp/Joseph Blatter is one person under two names in LFW)
  - people with ≥ 10 photos keep ≥ 97% of their photos in their main group

Manual: `uv run snapsort ingest <folder>` on a real library, then check the people counts and a few persons by eye.

### Phase 2 not yet validated

- **Single-file threshold 0.55:** only checked on two videos of one person. No video with several people has been tried.
- **Centroid matching (step 3):** the LFW numbers in Findings come from Louvain only (step 4). The two-pass LFW check covers step 3.
- **Look-alike relatives:** only the Williams sisters were measured.
- **Small extra persons:** a short head turn in a video formed its own 3-face person. It stays in the data, and only the `listPeople` rule decides whether it shows.
