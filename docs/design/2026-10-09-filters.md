# Filters design

Date: 2026-10-09
Status: draft, pending review

## Goal

Search the library by stacking filters: people, place, media kind and similar image. A video match comes back as time segments (`0:01–0:05, 0:10–0:16`), not just a file. This is CLI only for now. The Electron sidecar and the chatbot will later call the same `search()` function, so it takes the frontend contract's filter shape (`packages/contract/src/query.ts`).

## Scope

In:

- `snapsort/search.py`: the engine
- `snapsort search`, `snapsort people` and `snapsort places` in `snapsort/cli.py`
- `tests/search/test_search.py` and CLI/e2e tests

Out:

- the `label` (objects) filter. Its module (`objects`) has since landed, so it is a follow-up. `q` (text) has since been added as a scored filter, like similar (see Findings).
- `folder` filter. The backend has no folders table.
- adding `segments`, `combine` and `scope` to `packages/contract`. That needs agreement from the frontend side.
- cursors and pagination, facet counts, a vector index (sqlite-vec), sidecar wiring

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Stacking | Filters combine with AND by default: a file must pass every filter. `combine="any"` (`--or`) switches to OR: a file passes if any filter matches it. Similar image counts as a filter. | AND matches the frontend chips. OR covers "everything in Tokyo or with Anna". |
| Same file | By default, frame-based filters (person, similar) may match on different frames of the same file. `scope="frame"` (`--same-frame`) requires them to match on the same frame. Place and media kind always match the whole file. | Changed on 2026-10-10 from same frame to same file: "Anna and Ben" means both appear in the video. Same frame stays available for "on screen together". |
| Timeline marks | A video's matched frames are the frames where a frame-based filter hit. When only whole-file filters matched (or there are no filters), every frame is matched. | Marks show where the person or the similar frame is. A place filter would otherwise mark the whole video. |
| Similar image | Frames below `MIN_SCORE` cosine are dropped, and the rest are ranked by score | A cutoff makes "similar to X and Anna" a real filter with a meaningful match count |
| Segments | Matched timestamps of a video less than or equal to `GAP` = 2 s apart merge into one segment | At 1 fps this bridges one missed frame. Face detection drops single frames on head turns, and a strict rule would chop one appearance into pieces. |
| Evaluation | Each filter returns `{media_id: frame ids}`, or `{media_id: None}` for a whole-file match. AND intersects the files (and, under same frame, the frame sets). OR unions them. | Stacking is set algebra, each filter can be tested alone, and a new filter is one function |

## Engine (`snapsort/search.py`)

```python
MIN_SCORE: float   # set by the calibration step, see Findings
GAP = 2.0          # seconds

class QueryError(ValueError):
    """The query names something the library doesn't have. The message is shown to the user."""

@dataclass
class Segment:
    start: float          # ts of the first matched frame
    end: float            # ts of the last matched frame
    score: float | None   # best frame score in the segment; None without similar

@dataclass
class Hit:
    media_id: int
    path: str
    kind: str                                   # "image" | "video"
    added_at: str
    score: float | None                         # best frame score; None without similar
    matches: list[tuple[float, float | None]]   # (ts, score) per matched frame; videos only
    segments: list[Segment]                     # videos only
    best_ts: float | None                       # videos only

def search(conn, filters: list[dict], similar: dict | None = None,
           min_score: float = MIN_SCORE, sort: str | None = None,
           limit: int | None = None, gap: float = GAP,
           combine: str = "all", scope: str = "file") -> list[Hit]   # combine: all|any, scope: file|frame
```

`conn` comes from `snapsort.ingest.connect()`. Search never creates tables, because that write would wait on a running ingest. A library that was never grouped (no `persons` table) just has no persons.

### Filters

`filters` uses the contract's dict shape. The `source` key is ignored.

| Filter | Shape | Matches |
|---|---|---|
| person | `{"kind": "person", "ids": [3, 7], "match": "all" \| "any"}` | Files with a face result assigned to the persons in `person_faces`, marked with those frames. `all`: every person in the file (in one frame under `scope="frame"`). `any`: at least one. |
| place | `{"kind": "place", "name": "tokyo, japan"}` | The whole files whose `location` result label equals the name. Ingest lowercases labels, so the name is lowercased before comparing. |
| mediaKind | `{"kind": "mediaKind", "value": "image" \| "video"}` | The whole files of that kind |

`similar` is one of:

- `{"mediaId": 12, "ts": 4.0}`: the stored `image_embed` vector of that file's frame nearest to `ts`. Without `ts`, frame 0 is used. No model loads.
- `{"path": "/q.jpg"}`: the image decoded with `snapsort.ingest.load_image` and embedded with `ImageEmbed.embed`. The model loads.

The query file itself is not excluded, so it ranks first with score 1.0.

### Steps

1. Run each filter.
2. If `similar` is set, it becomes one more filter: frames with an `image_embed` vector at or above `min_score` cosine. Under AND only the files every other filter matched are read. Frame scores are `None` for frames similar didn't score.
3. Combine: AND keeps files every filter matched, marked with the union of their frames (the intersection under `scope="frame"`, dropping files with no shared frame). OR keeps files any filter matched, marked with the union. A file with no frame marks matches whole. No filters means every file, whole.
4. For a video:
   - `matches`: every marked frame as (ts, score), ordered by ts
   - `segments`: walk the sorted ts and start a new segment wherever the step from the previous ts is greater than `gap`. Matches at [1, 2, 3, 5, 6, 10] give 1–6 and 10–10.
   - `best_ts`: the highest-scoring frame, or the earliest when there are no scores
   - `score`: the best frame score

   An image has one frame: `score` is that frame's score, and `matches`, `segments` and `best_ts` are empty or `None`.
5. Sort, then cut to `limit`:
   - `similarity`: score descending, files without a score (possible under OR) last. This is the default when `similar` is set, and it is an error without `similar`.
   - `newest` / `oldest`: `media.added_at`, then id. `newest` is the default otherwise.
   - `name`: file basename

Ties keep id order.

Ceiling: step 2 reads 768 floats per candidate frame, about 300 MB at 100k frames when no other filter narrows the set (always, under OR). Mark it with a `ponytail:` comment. The upgrade is a cached vector matrix or sqlite-vec.

### Errors

`search()` raises `QueryError` for:

- a person filter with empty `ids`, or an id not in `persons`
- a place with no media
- an unsupported filter kind (`label`, `folder`, anything else)
- a `similar.mediaId` that doesn't exist or has no `image_embed` vectors (with a pointer to `snapsort ingest --modules image_embed`)
- a `similar.path` that doesn't exist or can't be decoded
- `sort="similarity"` without `similar`
- `combine` other than `all`/`any`, or `scope` other than `file`/`frame`

## CLI (`snapsort/cli.py`)

```
snapsort search [--person 3,7] [--any] [--place "tokyo, japan"] [--kind image|video]
                [--similar PATH | --similar-media ID[@TS]] [--min-score F]
                [--or] [--same-frame]
                [--sort similarity|newest|oldest|name] [--limit N] [--gap S] [--json]
snapsort people
snapsort places
```

`search` builds `filters` and `similar` from the flags and calls `search()`. All flags are optional, and they combine with AND unless `--or` is given. `--same-frame` sets `scope="frame"`. `--any` switches `--person` to `match: "any"`. `--similar` and `--similar-media` are mutually exclusive.

With Anna at 0:03 and Ben at 0:40 in one video: `--person A,B` matches it with marks `0:03, 0:40`; `--person A,B --same-frame` doesn't match it.

Default output, one line per file, then a count over the whole library:

```
/p/trip/clip.mov      video  0.81  0:01–0:05, 0:10–0:16
/p/trip/IMG_2031.jpg  image  0.77
12 of 340 files
```

The score column appears only when `--similar` is set. Times print as `m:ss`, or `h:mm:ss` from one hour on.

`--json` prints a list, using the contract's field names where they overlap:

```json
[{"id": 7, "kind": "video", "path": "/p/trip/clip.mov", "name": "clip.mov", "addedAt": "2026-10-09 10:00:00",
  "score": 0.81, "matches": [{"ts": 1.0, "score": 0.81}],
  "segments": [{"start": 1.0, "end": 5.0, "score": 0.81}], "bestFrameTs": 1.0}]
```

`people` prints `id  name  faces  files` per person, most files first, with an empty name until a person is named. `places` prints `place  files`, most files first, skipping location results without a place name. They exist so a CLI user can find the ids and names to filter on.

Exit codes follow the existing CLI:

- `0`: success, including zero matches
- `2`: no database, or a `QueryError` (message printed to stderr)

## Tests

`tests/search/test_search.py` inserts rows straight into a temp database, the same way `tests/group/test_group.py` does: media, frames, face results with `person_faces`, location results and `image_embed` unit vectors. No model runs.

- each filter alone, and person `all` vs `any`
- same file vs same frame: Anna at 0:01 and Ben at 0:05 in one video. `all` matches with both frames marked, and misses under `scope="frame"`.
- OR: place or person returns either kind of file; a whole-file match marks every frame
- OR with similar: files without a score sort last
- a per-file filter on a video: place + person returns that person's frames and nothing else
- similar: the cutoff drops frames, results are ordered by score, and frames without a vector are skipped
- segments: [1, 2, 3, 5, 6, 10] gives 1–6 and 10–10, and a 3 s step splits
- sort orders and `limit`
- each `QueryError` case

CLI tests call `cli.main(argv)`: every exit-2 case, the `--json` shape, and the `people` and `places` output.

One e2e test ingests two generated images with `image_embed`, then runs `snapsort search --similar` on one of them, which must rank first.

## Done when

- the tests pass
- a manual run on a real folder shows the `people` and `places` listings, person + place stacking, segments on a video, and `--similar` with the calibrated cutoff
